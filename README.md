# ⚡ Интерактивная карта ГЭС

Интерактивная карта шести малых ГТС Карельского перешейка (паспорт `HPPS` в `app.js`): рельеф, климат, гидрология, катастрофические сценарии.

## Возможности

- **Режимы**: 📜 история (реальные данные с 2023 г.), 🌤 прогноз (±период), 🌍 климат (модель до 2030 г.)
- **Сценарии**: норма, 🌊 паводок, ☀️ засуха, 💥 прорыв плотины (расчёт по реальным гидравлическим формулам + зона затопления), 📤 учебный сброс
  - паводок и засуха — **множители притока по календарной дате** (весенний разбор ~10 мая, летняя межень), а не по позиции бегунка: значение ряда в конкретной дате не зависит от того, где стоял слайдер в момент нажатия кнопки
  - множители настраиваются в паспорте станции: `floodAmp`, `floodDoy`, `droughtMin`
- **Физика прорыва плотины**: одномерные уравнения мелкой воды (Сен-Венана) вдоль реального русла: схема Годунова с потоком Гуно (HLL), шаг по условию Куранта, трение Мэннинга `n=0,04` (константа `MANNING_N` в `app.js` — она же в подписи паспорта и в README), корректная обработка сухого дна. Профиль дна — реальный (DEM, `terrain-data.js`). Проран моделируется водосливом широкого порога Q = 1,7·B·H^1,5 с опорожнением фактического объёма водохранилища за ~20 мин; ширина затопления по ячейкам — из рассчитанных глубин. Волна, скорость фронта и охват — результат расчёта, а не анимационная условность
- **Водные объекты**: реальный контур пруда Перовской МГЭС (`reservoirs-data.js`, снимок OSM при НПВ); в сценариях «паводок»/«засуха» берег масштабируется по площади зеркала вокруг створа плотины и не вылезает за чашу (`GES.reservoirScenario` + `shorelineRings`), при отступлении воды показывается пунктирная граница НПВ; для остальных станций зеркало строится эллипсом по смоделированной площади, при недоступности OSM — фолбэком из Overpass
- **Русла ниже плотин** (Селезнёвка, Андреевка, Перовка, Птичья, Пчелинка) встроены в `rivers-data.js` — офлайн-снимок OSM; отметки дна вдоль них — в `terrain-data.js`, именно они дают профиль для расчёта прорыва
- Данные: Open-Meteo API (температура, осадки, расход реки), Overpass API (русла); офлайн-режим с кэшем
- Графики мощности/уровня (Chart.js), таймлайн, PWA (манифест + service worker), доступность с клавиатуры

## Структура

| Файл | Назначение |
|---|---|
| `index.html` | разметка, подключение Leaflet/Chart.js |
| `app.js` | карта, состояние, сценарии, загрузка данных, анимации |
| **`model.js`** | **чистая математика без DOM и сети**: календарь, привязка рядов по дате, `simulate`, `releaseCalculate`, форматирование. В браузере — `window.GES`, в node — `module.exports`, поэтому тесты гоняют её напрямую |
| **`version.js`** | **единственный номер сборки** (`APP_VERSION`): из него штамп на странице и имя кэша оболочки в `sw.js` |
| `style.css` | стили, адаптив, доступность |
| `reservoirs-data.js` | реальные контуры водохранилищ (снимок OSM, упрощённые полигоны; `d`/`f` — копии `n`, см. шапку файла) |
| `rivers-data.js` | центрлинии русел ниже плотин (OSM, офлайн-снимок) |
| `terrain-data.js` | профиль дна русла (DEM-отметки Open-Meteo/SRTM) для расчёта прорыва |
| `climate-data.js` | климатическая модель по «модель клим.xlsx» (CMIP6, помесячно) |
| `sw.js` | service worker: кэш оболочки network-first, офлайн-фолбэк |
| `manifest.webmanifest`, `icons/` | PWA: установка, иконки (PNG генерируются скриптом) |
| `tools/make-icons.py` | исходник иконок → `icons/icon-192.png`, `icons/icon-512.png` (без зависимостей) |
| `tests/` | `npm test`: модель (13 тестов) + целостность сайта (15) |
| `tools/smoke.mjs` | `npm run smoke`: прогон страницы в jsdom с **настоящими** Leaflet и Chart.js — ловит то, что юнит-тесты не видят (см. «Диагностика») |
| `Перовка_финальный_алгоритм.js` | **эталон** учебного расчёта сброса; `model.js:releaseCalculate` сверяется с ним автотестом |

## Запуск и проверка

```bash
npm start          # python3 -m http.server 8080 → http://localhost:8080
npm test           # node --test: модель и целостность сборки
npm run lint       # node --check всех скриптов
npm run icons      # перегенерировать PNG-иконки PWA
npm run smoke      # 72 проверок живой страницы (нужно: npm i --no-save jsdom leaflet chart.js)
                   # SMOKE_OFFLINE=1 / SMOKE_NARROW=1 / SMOKE_MOTION=reduce / SMOKE_CHARTS=0
```

Зависимости для работы сайта не нужны — `package.json` нужен только для `npm test`/`npm start`.
`npm run smoke` — единственный прогон, который исполняет код страницы целиком (графики, карта,
анимации, обработчики); `jsdom`/`leaflet`/`chart.js` ставятся локально и в репозиторий не входят. CI (`.github/workflows/ci.yml`) гоняет lint, тесты и проверяет, что `icons/*.png` соответствуют `tools/make-icons.py`.

Деплой: `.github/workflows/pages.yml` (GitHub Pages из корня репозитория, без сборки).

## Диагностика

**Правило проверки.** После правок в `app.js` мало `npm test`: юнит-тесты не исполняют
код страницы. Нужен `npm run smoke` — он поднимает `index.html` в jsdom с настоящими
`leaflet`/`chart.js` и прогоняет загрузку, выбор станции, перемотку, прорыв и учебный сброс.
Подменять эти библиотеки в тесте фейками нельзя: именно так в v46 осталась незамеченной
поломка, описанная ниже.

**Что было сломано в v46 (сайт «перестал выполнять основные функции»).** Chart.js v4 берёт
тип контроллера из `config.type`; если `type:'line'` лежит внутри `options`, конструктор
не падает — падает первая же отрисовка сообщением
`"undefined" is not a registered controller.`. Отрисовка вызывается из `render()`,
из `requestAnimationFrame` анимаций и из таймера, поэтому одно неверное поле превращалось в
каскад: пустые графики, неподвижная перемотка, непрокрашенная волна прорыва и «лаги» в
режиме «Сброс» (исключение в каждом кадре). Исправлено в v47: конфиг графиков собирается в
`chartConfig(kind)`, где `type` — первый ключ, и это закреплено тестом
(`tests/site.test.mjs`, «type лежит в КОРНЕ конфига»). Попутно анимации стали дешевле:
кадры сброса не перерисовываются, если номер шага не изменился, а постоянные подсказки
участков обновляются не чаще 4 Гц; `render()` внутри анимации прорыва — не чаще 10 Гц.

**Почему иногда появляется плашка «Доступна новая версия — обновить».** Её показывает
`index.html`: новый service worker установился, но не смог перехватить управление
(`reg.waiting` не пустой) — только в этом случае перезагрузка реально нужна. В обычном
режиме плашки быть не должно: `install` в `sw.js` сам вызывает `skipWaiting()`, а оболочка
отдаётся **network-first**, то есть свежие `app.js`/`style.css` приходят с сервера при любой
загрузке, а кэш — это только офлайн-фолбэк. Клик по плашке сначала шлёт зависшему воркеру
`postMessage('skipWaiting')`, и только потом перезагружает страницу (один раз): `location.reload()`
без этого сообщения оставил бы воркер waiting, и плашка вернулась бы на месте.

**Если правки `app.js` «не видны» браузером** — это не network-first-оболочка, а
`CacheStorage` с именем `ges-shell-<APP_VERSION>`: номер сборки поднимают в `version.js`
(больше нигде — `npm run version:check` сверяет его с `package.json`), старый кэш `sw.js`
удаляет при активации. Отойти от устаревшего файла можно и кнопкой ⟳ в окне «Статус»
(чистит все ключи `ges_*` и кэш оболочки).

**Быстрая проверка без инструментов:** `curl -s localhost:8080/app.js | node --check -`,
`node --test`, `npm run smoke`.

## Как устроены данные и что показывать пользователю

- **Ряд расхода — это не створ у плотины.** `flood-api.open-meteo.com` отдаёт гидрологическую модель (CAMS/GLAFAS) на сетке ~0,1°; для пруда 0,1–0,6 МВт соседняя ячейка — уже другая река. Паспорт станции показывает фактические координаты ячейки и модель (`ряд: Open-Meteo flood (…), ячейка сетки 60,675, 28,935 · 0.1°`), чтобы ряд не выдавался за измерение.
- **Климат-режим — месяц, 15-е число**, история 1985–2025 + будущее 2041–2070 (`climate-data.js`); внешние климатические API не вызываются.
- **Ряды разной длины сводятся по дате**, а не по номеру элемента: `GES.buildTimeIndex` + `GES.alignIndex`. Иначе суточная история, месячный климат и локальная синтетика разъезжаются, и `render()` читает `undefined`.
- **Календарь только UTC** (`GES.dayRange`): обход через `setDate` + `toISOString` на переходах через летнее время даёт дубль дня и пропуск следующего — ряд смещается относительно данных Open-Meteo (`timezone=UTC`) на сутки.
- **Кэш**: данные — в `localStorage` (`ges_cache_v19`, TTL: история 12 ч, прогноз 30 мин, климат 7 сут) + фоновая ревалидация; русла и контуры OSM — отдельными ключами с TTL 30 сут. Кэш данных читается один раз и держится в памяти, запись — пачкой (`requestIdleCallback`). Кнопка ⟳ чистит **все** ключи `ges_*` и кэш оболочки.
- **Зеркало воды в сценариях — отдельная схема, а не вывод `simulate()`.** Правило эксплуатации в модели держит уровень на целевой отметке: при ×3 приток уходит в холостой сброс, при ×0,15 приток и так ниже пропускной способности, — поэтому отметка на «паводок»/«засуху» не реагировала вовсе. Схема (`model.js`: `SHORE_CLAMP`, `reservoirScenario`, `applyReservoirScenario`) даёт сдвиг отметки `Δh = 0,5·(НПУ−УМО)/3 · ln k`, площадь `A/A_НПУ = 1 + Δh/d̄` (где `d̄ = V_полный/A_НПУ` — средняя глубина чаши из паспорта) и линейный масштаб берега `s = √(A/A_НПУ)`. Множитель `k` — **годовая водность** (для паводка вершина колокола `scenarioFactor`, для засухи её нижняя граница) с подмесью текущего дня 30%: без этого зеркало менялось бы только в мае и оставалось неподвижным на любой другой дате. Применяется к КОПИИ ряда, мощность и напор поправкой не трогаются (для пруда 0,15 МВт это доли киловатт).
* **Берег масштабируется вокруг плотины, а не вокруг центра bbox** (`GES.shorelineRings`), а при сработке каждая вершина, оказавшаяся вне чаши, притягивается к ближайшему берегу (`pullInsideRing`). Равномерный масштаб вокруг центра на серповидном заливе давал «водохранилище съехало»: вода отрывалась от створа на ~60 м, а 40 из 67 вершин вылезали наружу контура. Долю площади в карточке считают по нарисованному кольцу (шнуровка), а не как `s²` — после посадки в чашу площадь меньше «бумажной». Варианты `d`/`f` в `reservoirs-data.js` — побайтовые копии `n`, переключение колец ничего не давало, поэтому они больше не используются.
- **Офлайн**: при недоступном API станции считаются локальной синтетикой, статус честно помечает 🔴; повторная проверка каждые 30 с, при восстановлении сети данные докачиваются сами.

## Интерфейс

- Панели (список+паспорт, графики) перетаскиваются за заголовок и ресайзятся за угол; положение и размеры сохраняются в `localStorage` (`ges_layout_v1`) и не дают увести панель за край экрана; двойной клик по заголовку — сброс.
- Окно «Статус» тоже переставляется: тащится за любую точку, кроме кнопки `⟳` (двойной клик — вернуть на место). По умолчанию опущено до `top:136px` и имеет `z-index:900` — то есть стоит под переключателем слоёв Leaflet и не лежит поверх него, поэтому раскрытый список базовых слоёв (OSM / рельеф / спутник) остаётся кликабельным. Позиция помнится в `ges_layout_v1`, размер окно не закрепляет (режим `moveOnly`) — текст статуса меняет длину.
- Графики можно закрыть: `✕` в шапке панели, `Esc` или тумблер «📈». На месте закрытой панели появляется кнопка «📈 Графики» (на телефоне её роль играет тот же тумблер в `#mobileBar`), а выбор следующей станции больше не показывает панель вопреки закрытию. Намерение хранится в `localStorage` под `ges_charts_v1` и переживает перезагрузку; при показе вызывается `chart.resize()` — иначе canvas из `display:none` остаётся нулевого размера и ряды не видны.
- До 900 px панели складываются в выдвижные ящики (кнопки «☰ Станции» и «📈 График»), `Esc` закрывает их по одному — список станций и графики доступны и на телефоне.
- `Пробел` — пуск/пауза перемотки, `←`/`→` в переключателе режимов, `Tab` по списку станций; у цветов меток есть легенда, у осей — русские разделители (`GES.num`).
- Окно «📤 ДОПОЛНИТЕЛЬНЫЙ СБРОС» на Перовской ставится **под** маркером плотины, а не над ним: Leaflet привязывает поповер нижним краем, поэтому `placePopupUnder()` сдвигает его на измеренную высоту контейнера (`offset.y = высота + 7`), а CSS-класс `.pop-under` переворачивает «хвост». Тем же движком окно закрывается при выключении сценария (раньше оно оставалось висеть на карте).
- `prefers-reduced-motion: reduce` — без полётов карты и прокрутки волны: показывается сразу финальный охват прорыва.

## Что решено отложить

- **Станции Северного Кавказа** (Гизельдонская 22,8 МВт, Гунибская 15 МВт, Баксанская 27 МВт) описаны в исходном README, но в `HPPS` и в файлах данных их нет: нужны паспорта, контуры, русла и DEM-профили. Пока описание приведено к тому, что реально работает, — шесть ГТС Карельского перешейка.
- `RIVER_COURSES`/`RIVER_ELEV`/`CLIMATE_DATA` содержат станцию **`yash`**, которой нет в паспорте `HPPS` (русло 96 точек + профиль + 41 год климата). Либо её надо вернуть в `HPPS`, либо удалить данные; пока она внесена в `KNOWN_ORPHANS` в `tests/site.test.mjs`, чтобы тест не был вечно красным.
- `*.xlsx`/`*.docx` (1,4 МБ) лежат в git как источник данных; вынос в `data-src/` + генерация `*-data.js` — отдельная задача.
- Leaflet/Chart.js подключаются с CDN (есть `preconnect`, в кэше оболочки они лежат). Полностью локальная копия (`vendor/`) сняла бы последнюю зависимость от сети — но добавила бы ~350 КБ в репозиторий.
