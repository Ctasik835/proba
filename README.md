# ⚡ Интерактивная карта ГЭС

Интерактивная карта шести малых ГТС Карельского перешейка (паспорт `HPPS` в `app.js`): рельеф, климат, гидрология, катастрофические сценарии.

## Возможности

- **Режимы**: 📜 история (реальные данные с 2023 г.), 🌤 прогноз (±период), 🌍 климат (модель до 2030 г.)
- **Сценарии**: норма, 🌊 паводок, ☀️ засуха, 💥 прорыв плотины (расчёт по реальным гидравлическим формулам + зона затопления), 📤 учебный сброс
  - паводок и засуха — **множители притока по календарной дате** (весенний разбор ~10 мая, летняя межень), а не по позиции бегунка: значение ряда в конкретной дате не зависит от того, где стоял слайдер в момент нажатия кнопки
  - множители настраиваются в паспорте станции: `floodAmp`, `floodDoy`, `droughtMin`
- **Физика прорыва плотины**: одномерные уравнения мелкой воды (Сен-Венана) вдоль реального русла: схема Годунова с потоком Гуно (HLL), шаг по условию Куранта, трение Мэннинга `n=0,04` (константа `MANNING_N` в `app.js` — она же в подписи паспорта и в README), корректная обработка сухого дна. Профиль дна — реальный (DEM, `terrain-data.js`). Проран моделируется водосливом широкого порога Q = 1,7·B·H^1,5 с опорожнением фактического объёма водохранилища за ~20 мин; ширина затопления по ячейкам — из рассчитанных глубин. Волна, скорость фронта и охват — результат расчёта, а не анимационная условность
- **Водные объекты**: реальный контур пруда Перовской МГЭС (`reservoirs-data.js`, снимок OSM) с морфингом норма/засуха/паводок по вариантам `n`/`d`/`f`; для остальных станций зеркало строится эллипсом по смоделированной площади, при недоступности OSM — фолбэком из Overpass
- **Русла ниже плотин** (Селезнёвка, Андреевка, Перовка, Птичья, Пчелинка) встроены в `rivers-data.js` — офлайн-снимок OSM; отметки дна вдоль них — в `terrain-data.js`, именно они дают профиль для расчёта прорыва
- Данные: Open-Meteo API (температура, осадки, расход реки), Overpass API (русла); офлайн-режим с кэшем
- Графики мощности/уровня (Chart.js), таймлайн, PWA (манифест + service worker), доступность с клавиатуры

## Структура

| Файл | Назначение |
|---|---|
| `index.html` | разметка, подключение Leaflet/Chart.js |
| `app.js` | карта, состояние, сценарии, загрузка данных, анимации |
| **`model.js`** | **чистая математика без DOM и сети**: календарь, привязка рядов по дате, `simulate`, `releaseCalculate`, форматирование. В браузере — `window.GES`, в node — `module.exports`, поэтому тесты гоняют её напрямую |
| **`version.js`** | **единственный номер сборки** (`APP_VERSION`): из него штамп на странице и имя кэша оболочки в `sw.js` |
| `style.css` | стили, адаптив, доступность |
| `reservoirs-data.js` | реальные контуры водохранилищ (снимок OSM, упрощённые полигоны) |
| `rivers-data.js` | центрлинии русел ниже плотин (OSM, офлайн-снимок) |
| `terrain-data.js` | профиль дна русла (DEM-отметки Open-Meteo/SRTM) для расчёта прорыва |
| `climate-data.js` | климатическая модель по «модель клим.xlsx» (CMIP6, помесячно) |
| `sw.js` | service worker: кэш оболочки network-first, офлайн-фолбэк |
| `manifest.webmanifest`, `icons/` | PWA: установка, иконки (PNG генерируются скриптом) |
| `tools/make-icons.py` | исходник иконок → `icons/icon-192.png`, `icons/icon-512.png` (без зависимостей) |
| `tests/` | `npm test`: модель (13 тестов) + целостность сайта (14) |
| `Перовка_финальный_алгоритм.js` | **эталон** учебного расчёта сброса; `model.js:releaseCalculate` сверяется с ним автотестом |

## Запуск и проверка

```bash
npm start          # python3 -m http.server 8080 → http://localhost:8080
npm test           # node --test: модель и целостность сборки
npm run lint       # node --check всех скриптов
npm run icons      # перегенерировать PNG-иконки PWA
```

Зависимости для работы сайта не нужны — `package.json` нужен только для `npm test`/`npm start`. CI (`.github/workflows/ci.yml`) гоняет lint, тесты и проверяет, что `icons/*.png` соответствуют `tools/make-icons.py`.

Деплой: `.github/workflows/pages.yml` (GitHub Pages из корня репозитория, без сборки).

## Как устроены данные и что показывать пользователю

- **Ряд расхода — это не створ у плотины.** `flood-api.open-meteo.com` отдаёт гидрологическую модель (CAMS/GLAFAS) на сетке ~0,1°; для пруда 0,1–0,6 МВт соседняя ячейка — уже другая река. Паспорт станции показывает фактические координаты ячейки и модель (`ряд: Open-Meteo flood (…), ячейка сетки 60,675, 28,935 · 0.1°`), чтобы ряд не выдавался за измерение.
- **Климат-режим — месяц, 15-е число**, история 1985–2025 + будущее 2041–2070 (`climate-data.js`); внешние климатические API не вызываются.
- **Ряды разной длины сводятся по дате**, а не по номеру элемента: `GES.buildTimeIndex` + `GES.alignIndex`. Иначе суточная история, месячный климат и локальная синтетика разъезжаются, и `render()` читает `undefined`.
- **Календарь только UTC** (`GES.dayRange`): обход через `setDate` + `toISOString` на переходах через летнее время даёт дубль дня и пропуск следующего — ряд смещается относительно данных Open-Meteo (`timezone=UTC`) на сутки.
- **Кэш**: данные — в `localStorage` (`ges_cache_v19`, TTL: история 12 ч, прогноз 30 мин, климат 7 сут) + фоновая ревалидация; русла и контуры OSM — отдельными ключами с TTL 30 сут. Кэш данных читается один раз и держится в памяти, запись — пачкой (`requestIdleCallback`). Кнопка ⟳ чистит **все** ключи `ges_*` и кэш оболочки.
- **Офлайн**: при недоступном API станции считаются локальной синтетикой, статус честно помечает 🔴; повторная проверка каждые 30 с, при восстановлении сети данные докачиваются сами.

## Интерфейс

- Панели (список+паспорт, графики) перетаскиваются за заголовок и ресайзятся за угол; положение и размеры сохраняются в `localStorage` (`ges_layout_v1`) и не дают увести панель за край экрана; двойной клик по заголовку — сброс.
- До 900 px панели складываются в выдвижные ящики (кнопки «☰ Станции» и «📈 График»), `Esc` закрывает — список станций и графики доступны и на телефоне.
- `Пробел` — пуск/пауза перемотки, `←`/`→` в переключателе режимов, `Tab` по списку станций; у цветов меток есть легенда, у осей — русские разделители (`GES.num`).
- `prefers-reduced-motion: reduce` — без полётов карты и прокрутки волны: показывается сразу финальный охват прорыва.

## Что решено отложить

- **Станции Северного Кавказа** (Гизельдонская 22,8 МВт, Гунибская 15 МВт, Баксанская 27 МВт) описаны в исходном README, но в `HPPS` и в файлах данных их нет: нужны паспорта, контуры, русла и DEM-профили. Пока описание приведено к тому, что реально работает, — шесть ГТС Карельского перешейка.
- `RIVER_COURSES`/`RIVER_ELEV`/`CLIMATE_DATA` содержат станцию **`yash`**, которой нет в паспорте `HPPS` (русло 96 точек + профиль + 41 год климата). Либо её надо вернуть в `HPPS`, либо удалить данные; пока она внесена в `KNOWN_ORPHANS` в `tests/site.test.mjs`, чтобы тест не был вечно красным.
- `*.xlsx`/`*.docx` (1,4 МБ) лежат в git как источник данных; вынос в `data-src/` + генерация `*-data.js` — отдельная задача.
- Leaflet/Chart.js подключаются с CDN (есть `preconnect`, в кэше оболочки они лежат). Полностью локальная копия (`vendor/`) сняла бы последнюю зависимость от сети — но добавила бы ~350 КБ в репозиторий.
